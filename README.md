# depviz — граф зависимостей пакетов Alpine Linux

## Общее описание

`depviz` — консольный инструмент визуализации графа зависимостей
для менеджера пакетов Alpine Linux (apk). Готовые менеджеры пакетов
и сторонние библиотеки не используются: только стандартная
библиотека Python.

Практическая работа по дисциплине «Конфигурационное управление»,
вариант №4.

## Как получаются зависимости

Из URL репозитория (например
`https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64`) скачивается
`APKINDEX.tar.gz`, из архива извлекается файл `APKINDEX` и разбирается
вручную (модуль `src/depviz/apk.py`):

- записи пакетов разделены пустой строкой;
- `P:` — имя пакета, `D:` — зависимости, `p:` — что пакет предоставляет;
- ограничения версий (`=`, `>=`, `<`, `>`, `~`) отбрасываются;
- виртуальные имена (`so:libz.so.1`, `cmd:sh`, `pc:zlib`) заменяются
  пакетом, который их предоставляет (`p:`);
- конфликты (`!имя`) и зависимость пакета от самого себя пропускаются;
- имя, которого нет в репозитории, остаётся как есть (его даёт пакет
  из другого репозитория, например `community`).

## Граф зависимостей

Граф строится в `src/depviz/graph.py` обходом в ширину (BFS)
с рекурсией: функция `bfs_levels` обрабатывает текущий уровень
пакетов и вызывает себя для следующего уровня. Ключи построенного
графа служат множеством посещённых вершин, поэтому циклы
(`A -> B -> A`) и петли (`D -> D`) не приводят к зацикливанию:
каждый пакет попадает в граф один раз, а ребро назад сохраняется.

## Обратные зависимости

С опцией `--reverse` выводятся все пакеты, которые прямо или
транзитивно зависят от заданного. Функция `reverse_map` разворачивает
рёбра графа, а `reverse_dependencies` обходит развёрнутый граф тем же
рекурсивным BFS. Пакеты выводятся в порядке обхода, то есть сначала
прямые обратные зависимости, затем следующие уровни.

## Тестовый репозиторий (режим `test`)

Вместо URL указывается путь к текстовому файлу, где пакеты названы
большими латинскими буквами (`src/depviz/testrepo.py`):

```text
# комментарий
A: B C
B: D
C: D E
D:
```

- одна строка — один пакет и его прямые зависимости через пробел;
- пустые строки и строки с `#` пропускаются;
- пакет, упомянутый только как зависимость, — лист без зависимостей;
- ошибки формата (нет `:`, неверное имя, повторное описание)
  сообщаются с номером строки.

Готовые примеры лежат в каталоге `examples/`: `simple.txt` (дерево),
`cycle.txt` (цикл и петля), `complex.txt` (ромбы, общие зависимости,
пакет без описания).

## Визуализация

Модуль `src/depviz/d2.py` формирует описание графа на языке диаграмм
[D2](https://d2lang.com/), и приложение выводит его на экран:

- первая строка `direction: right` — граф слева направо;
- каждое ребро «пакет -> зависимость» — отдельная строка;
- пакет без зависимостей объявляется отдельной строкой, чтобы граф
  из одной вершины тоже был виден;
- имена берутся в кавычки, поэтому допустимы `libstdc++` и подобные.

Примеры для трёх пакетов репозитория
`https://dl-cdn.alpinelinux.org/alpine/v3.20/main/aarch64`:
`curl` (35 строк D2), `openssh-client` (41) и `python3` (40).

## Сравнение со штатным инструментом `apk dot`

Штатная визуализация Alpine — команда `apk dot ПАКЕТ` (apk-tools
2.14.4), она выводит граф на языке Graphviz. Сравнение проводилось
в контейнере `alpine:3.20` (aarch64) только с репозиторием `main`,
`depviz` запускался на том же репозитории:

```sh
docker run --rm alpine:3.20 sh -c '
  echo https://dl-cdn.alpinelinux.org/alpine/v3.20/main \
    > /etc/apk/repositories
  apk update >/dev/null && apk dot curl'
```

Рёбра `apk dot` сравнивались с рёбрами `depviz` после удаления версий
из имён и повторов:

| Пакет | Рёбер `apk dot` | Рёбер `depviz` | Результат |
|---|---|---|---|
| `python3` | 37 | 37 | полностью совпадают |
| `openssh-client` | 35 | 37 | у `depviz` на 2 ребра больше |
| `curl` | 48 | 33 | у `apk dot` на 15 рёбер больше |

Причины расхождений:

1. **Альтернативные поставщики (`curl`).** `ca-certificates` зависит
   от виртуального `/bin/sh`, который в `main` дают три пакета:
   `busybox-binsh`, `dash-binsh`, `yash-binsh`. `apk dot` рисует всех
   поставщиков вместе с их зависимостями (`dash`, `yash`,
   `libncursesw`), а взаимоисключающие варианты выделяет красным.
   `depviz` берёт первого поставщика из индекса (`busybox-binsh`):
   именно его apk ставит по умолчанию, остальные 15 рёбер — варианты,
   которые не устанавливаются вместе.
2. **Виртуальный корень (`openssh-client`).** У `openssh-client` нет
   своей записи в индексе, его предоставляют `openssh-client-default`
   и `openssh-client-krb5`. `apk dot` сразу начинает граф с них,
   а `depviz` добавляет вершину `openssh-client` и два ребра к ним.
   Остальные рёбра совпадают.
3. **Оформление.** `apk dot` пишет версии в именах
   (`musl-1.2.5-r4`), подписывает рёбра виртуальными именами
   (`so:libc.musl-aarch64.so.1`) и рисует повторные рёбра, если
   зависимость указана дважды (`libcurl` и `so:libcurl.so.4`).
   `depviz` показывает только имена пакетов и одно ребро на пару.
4. **Архитектура.** Зависимости `so:` зависят от архитектуры
   (`libc.musl-x86_64.so.1` и `libc.musl-aarch64.so.1`), поэтому
   сравнивать нужно индексы одной архитектуры.

## Параметры

| Опция | Описание |
|---|---|
| `-p`, `--package` | имя анализируемого пакета (обязательно) |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательно) |
| `-m`, `--mode` | режим работы: `real` (по умолчанию) или `test` |
| `--reverse` | вывести обратные зависимости вместо графа |

Обработка ошибок (код завершения 1, сообщение в stderr):

- пустое имя пакета или недопустимые символы в нём;
- в режиме `test` имя пакета не из больших латинских букв;
- пустой адрес репозитория, URL не по http/https или без сервера;
- в режиме `test` файл не найден, это каталог или нет прав на чтение;
- неизвестный режим работы;
- отсутствует обязательная опция (сообщение argparse, код 2);
- репозиторий недоступен (сеть, HTTP 404) или архив повреждён;
- пакета нет в репозитории.

## Сборка и тесты

Нужен Python 3.10 или новее, сборка не требуется.

```sh
make test          # запустить тесты
./run.sh --help    # справка
```

## Примеры использования

Граф выводится на языке диаграмм D2 (см. раздел «Визуализация»).

Тестовый репозиторий с циклом и петлёй:

```sh
$ ./run.sh -p A -r examples/cycle.txt -m test
direction: right
"A" -> "B"
"B" -> "C"
"C" -> "A"
"C" -> "D"
"D" -> "D"
```

Подграф с середины графа:

```sh
$ ./run.sh -p G -r examples/complex.txt -m test
direction: right
"G" -> "H"
"G" -> "B"
"H"
"B" -> "E"
"E" -> "H"
```

Обратные зависимости: кто зависит от `D` в простом дереве, от `A`
в цикле, от `F` (пакета без описания) и от корня `A`:

```sh
$ ./run.sh -p D -r examples/simple.txt -m test --reverse
B
C
A

$ ./run.sh -p A -r examples/cycle.txt -m test --reverse
C
B

$ ./run.sh -p F -r examples/complex.txt -m test --reverse
C
A

$ ./run.sh -p A -r examples/simple.txt -m test --reverse
От пакета 'A' не зависит ни один пакет
```

Реальный репозиторий и построение картинки
(нужен [d2](https://d2lang.com/)):

```sh
$ ./run.sh -p curl -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
direction: right
"curl" -> "libcurl"
"curl" -> "musl"
"curl" -> "zlib"
"libcurl" -> "ca-certificates"
...

$ ./run.sh -p curl -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 > curl.d2
$ d2 --layout=elk curl.d2 curl.svg
```

Ошибки:

```sh
$ ./run.sh -p A -r nofile -m test
Ошибка: файл тестового репозитория не найден: 'nofile'

$ ./run.sh -p nosuchpkg -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
Ошибка: пакет 'nosuchpkg' не найден в репозитории
```
