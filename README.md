# depviz — граф зависимостей пакетов Alpine Linux

## Общее описание

`depviz` — консольный инструмент визуализации графа зависимостей
для менеджера пакетов Alpine Linux (apk). Готовые менеджеры пакетов
и сторонние библиотеки не используются: только стандартная
библиотека Python.

Практическая работа по дисциплине «Конфигурационное управление»,
вариант №4.

## Как получаются зависимости

Из URL репозитория (например
`https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64`) скачивается
`APKINDEX.tar.gz`, из архива извлекается файл `APKINDEX` и разбирается
вручную (модуль `src/depviz/apk.py`):

- записи пакетов разделены пустой строкой;
- `P:` — имя пакета, `D:` — зависимости, `p:` — что пакет предоставляет;
- ограничения версий (`=`, `>=`, `<`, `>`, `~`) отбрасываются;
- виртуальные имена (`so:libz.so.1`, `cmd:sh`, `pc:zlib`) заменяются
  пакетом, который их предоставляет (`p:`);
- конфликты (`!имя`) и зависимость пакета от самого себя пропускаются;
- имя, которого нет в репозитории, остаётся как есть (его даёт пакет
  из другого репозитория, например `community`).

## Граф зависимостей

Граф строится в `src/depviz/graph.py` обходом в ширину (BFS)
с рекурсией: функция `bfs_levels` обрабатывает текущий уровень
пакетов и вызывает себя для следующего уровня. Ключи построенного
графа служат множеством посещённых вершин, поэтому циклы
(`A -> B -> A`) и петли (`D -> D`) не приводят к зацикливанию:
каждый пакет попадает в граф один раз, а ребро назад сохраняется.

## Тестовый репозиторий (режим `test`)

Вместо URL указывается путь к текстовому файлу, где пакеты названы
большими латинскими буквами (`src/depviz/testrepo.py`):

```text
# комментарий
A: B C
B: D
C: D E
D:
```

- одна строка — один пакет и его прямые зависимости через пробел;
- пустые строки и строки с `#` пропускаются;
- пакет, упомянутый только как зависимость, — лист без зависимостей;
- ошибки формата (нет `:`, неверное имя, повторное описание)
  сообщаются с номером строки.

Готовые примеры лежат в каталоге `examples/`: `simple.txt` (дерево),
`cycle.txt` (цикл и петля), `complex.txt` (ромбы, общие зависимости,
пакет без описания).

## Параметры

| Опция | Описание |
|---|---|
| `-p`, `--package` | имя анализируемого пакета (обязательно) |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательно) |
| `-m`, `--mode` | режим работы: `real` (по умолчанию) или `test` |

Обработка ошибок (код завершения 1, сообщение в stderr):

- пустое имя пакета или недопустимые символы в нём;
- в режиме `test` имя пакета не из больших латинских букв;
- пустой адрес репозитория, URL не по http/https или без сервера;
- в режиме `test` файл не найден, это каталог или нет прав на чтение;
- неизвестный режим работы;
- отсутствует обязательная опция (сообщение argparse, код 2);
- репозиторий недоступен (сеть, HTTP 404) или архив повреждён;
- пакета нет в репозитории.

## Сборка и тесты

Нужен Python 3.10 или новее, сборка не требуется.

```sh
make test          # запустить тесты
./run.sh --help    # справка
```

## Примеры использования

Граф выводится строками «пакет: зависимости» в порядке обхода.

Тестовый репозиторий с циклом:

```sh
$ ./run.sh -p A -r examples/cycle.txt -m test
A: B
B: C
C: A D
D: D
```

Подграф с середины графа:

```sh
$ ./run.sh -p G -r examples/complex.txt -m test
G: H B
H:
B: E
E: H
```

Реальный репозиторий:

```sh
$ ./run.sh -p curl -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
curl: libcurl musl zlib
libcurl: ca-certificates brotli-libs musl c-ares libcrypto3 libidn2 ...
musl:
zlib: musl
...
```

Ошибки:

```sh
$ ./run.sh -p A -r nofile -m test
Ошибка: файл тестового репозитория не найден: 'nofile'

$ ./run.sh -p nosuchpkg -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
Ошибка: пакет 'nosuchpkg' не найден в репозитории
```
